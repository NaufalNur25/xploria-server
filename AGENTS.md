# Hardware Server & HAL Guidelines (`xploria-server/`)

Guidelines and development standards for the **Xploria Raspberry Pi Edge Server & Hardware Abstraction Layer (HAL)**.

---

## 1. Quick Commands & Execution

```bash
# Install dependencies
pip3 install -r requirements.txt

# Run Daemon directly (Development / Pi local)
python3 main.py
# (Starts WebSocket server listening on ws://0.0.0.0:9002)

# Pin Configuration CLI
python3 pin_config_cli.py interactive       # Interactive TUI menu
python3 pin_config_cli.py list              # List current pin assignments
python3 pin_config_cli.py set 1 17 --desc "LED Ruang Tamu"  # Map Logical 1 -> BCM 17
python3 pin_config_cli.py delete 1          # Delete mapping for Logical Pin 1

# Run Unit Tests (uses hardware mocks; runnable on any OS without physical Pi)
python -m unittest discover -s tests -v
```

## 2. Core Architecture & Virtual HAL (`xploria_hal`)

The server hosts a WebSocket daemon that receives Python code generated by the Flutter Blockly workspace and executes it in a sandboxed, cooperative multi-threaded environment.

### Virtual Module Injection
The virtual module `xploria_hal` is dynamically injected into `sys.modules["xploria_hal"]` via `HalProxy` wrappers with automatic stop-checking. It exposes:

- **`sensor`**:
  - Digital: IR obstacle, PIR motion, rain sensor, soil moisture, line follower, gas MQ-9 DO.
  - Analog (via I2C ADS1115): Water level, LDR light level, MQ-9 gas analog percentage.
  - Special workers: Background daemon threads for non-blocking DHT22 (temperature & humidity) and HC-SR04 ultrasonic readings.
- **`motor`**: L298N DC motors (`run_dc`, `set_fan`, `stop_dc`), standard 180° PWM servo (`set_servo`), and 360° continuous servo (`set_servo360`).
- **`led` / `rgb` / `ledstrip`**: Single GPIO LEDs, active-low common-anode RGB LEDs, and WS2812B NeoPixel strips (`rpi_ws281x`).
- **`rfid`**: PN532 via I2C (`read_uid`, `register_card`, `unregister_card`, `is_allowed`).
- **`audio` / `voice`**:
  - WAV sound playback (`aplay` / `winsound` mock) and preset audio library.
  - Dynamic student voice recording upload with memory quota eviction and slot management.
  - Indonesian voice command intent parser with word-order invariance, affix matching, and negation rejection.
- **`hospital` / `hospital_widgets`**:
  - `HospitalWidgetSession` runtime for interactive hospital forms, triage queues, and barcode scanner dispatches.
  - Event deduplication via `BoundedSeen` (capacity 4096) to prevent memory bloat during long sessions.
  - Jitsi Meet video consultation delegation triggers.
- **`agri`**:
  - Smart Agriculture dosing pumps (A, B, pH Up, pH Down), drip irrigation valve, ultrasonic mist maker.
  - YF-S201 flow meter pulse counting, greenhouse roof servo, and telemetry getters.
- **`face`**:
  - UART/Camera face recognition, enrollment, capture, and clear.
  - Team HW UART frame protocol: `FACE` + uint32 LE length + JPEG payload.
- **`telemetry` & `pin`**: Real-time pub/sub telemetry queue and low-level digital/PWM pin controls.

## 3. WebSocket Protocol & Threading Invariants

- **Default Port**: `9002` (WebSocket protocol v1).
- **Execution Thread Isolation**:
  - Dedicated `USER_EXECUTOR_WORKERS = 4` `ThreadPoolExecutor` ensures student programs (even tight infinite loops) never block the asyncio WebSocket event loop.
  - Cooperative preemption: `HalProxy.check_stop_func` checks the stop event before invoking any hardware function.
  - Dual execution tracking: `_global_primary_execution` (main Blockly code) and `_global_telemetry_execution` (periodic background sensor loop).
- **Audio Upload Safety**:
  - Checked against `MAX_UPLOAD_B64_CHARS = 700_000` (~512KB audio) before decoding to prevent Pi 3B memory exhaustion.
  - Gated by `_audio_upload_semaphore` (1 concurrent upload).
- **Supported WebSocket Message Types**:
  - Inbound:
    - `capabilities` → Handshake responding with server features.
    - `run` → Runs Python code in worker thread with stdout/stderr real-time streaming.
    - `stop` → Gracefully cancels active primary execution and telemetry workers.
    - `hospital_widget_event` / `hospital_widget_result` → Interactive hospital widget transactions.
    - `upload_audio` → Base64 WAV upload for custom sound slots.
    - `voice_command` → Natural language voice intent dispatch.
    - `control` → Direct actuator control (ESP32-CAM flash/capture, hospital door locks, agri pumps/valves).
    - `pin_mapping` → Reload, set, or list pin mappings from SQLite `pin_config.db`.
  - Outbound:
    - `telemetry` & `telemetry_delta`: Sensor readings and actuator status updates.
    - `telemetry_heartbeat`: Liveness indicator.
    - `output` & `error`: Console logs and Python tracebacks.
    - `ack`, `camera_result`, `voice_result`, `audio_upload_result`, `pin_mapping_list`.

## 4. Production Deployment (systemd)

On the physical Raspberry Pi:
- Installer: `sudo ./install.sh`
- Creates system user `xploria` with permissions for `gpio`, `i2c`, and `spi` groups.
- Service unit: `xploria-daemon.service`
- Check service logs: `sudo journalctl -u xploria-daemon -f`
- Run CLI as service user to avoid SQLite file ownership issues:
  ```bash
  sudo -u xploria /home/xploria/xploria-server/.venv/bin/python3 pin_config_cli.py list
  ```
